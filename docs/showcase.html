Agent memory corrupts under concurrency. The fixes are published — so why is the bug still shipping?

When several AI agents write to one memory store at the same time, writes are lost silently. Eight failure modes are documented, most with published fixes and several with released code. Four widely used libraries still carry 14 open defects between them. The bottleneck is not knowledge — it is adoption.

The problem

Agent memory systems are benchmarked almost entirely on recall — can the agent find the right fact later. They are barely benchmarked on whether they stay correct when two agents write at once.

The mechanism is ordinary: read a record, modify it, write it back, with no synchronisation. Two writers read the same snapshot and the last write wins. What makes it expensive in agent systems is that it is silent. No exception is raised and nothing is logged, so it does not surface as an alert — it surfaces later as a wrong answer, with no trail back to the cause.

The commercial consequence is not downtime, it is unaccountable wrongness. Nothing raises an exception and nothing is logged, so corruption does not arrive as an incident — it arrives as an agent confidently asserting something false, with no trail back to the cause. That cost lands on whoever deployed the agent.

It also scales the wrong way: loss rises with writer count, so the defect worsens exactly as multi-agent deployment grows.
