Memory for Autonomous LLM Agents: Mechanisms, Evaluation, and Emerging Frontiers | 2026 (Mar) | arXiv survey 2603.07670 | https://arxiv.org/abs/2603.07670 | MOST DIRECT HIT. Names concurrent-write consistency as an open frontier but only as a one-paragraph question, no solution, no cited work. Sec 6.6 (multi-agent/SWE): "consistency under concurrent writes—what happens when two agents update shared memory simultaneously?" Sec 9.6 "Multi-agent memory governance": "consensus protocols for concurrent writes" ... A Survey of Agent Memory in the Second Half (Towards Self-Evolving and Long-Horizon Agents) | 2026 (Jan; TMLR 07/2026) | arXiv survey 2602.06052 | https://arxiv.org/abs/2602.06052 | Sec 4.2.3 "Memory Isolation and Conflicts" is the closest survey treatment: "memory is read and written by multiple agents rather than updated in a single, sequential loop... there might be consistency conflicts: different agents may write facts that contradict each other, and outdated information may not be removed". Solutions surveyed are write-time gating (Memory-R1: single memory-manager agent is "the only agent allowed to mutate memory"; WebCoach: write only after episode completes) and feedback-loop consistency (EvoMem). These are single-writer / LLM-judgment approaches, not isolation levels, CAS, or lost-update analysis. Also notes shared pools need "coordination strategies to avoid conflicts when multiple agents update the same information" (Sec 4.2.1). Sec 9.2 future work is about collaborative/social memory and "ownership, access, responsibility", not concurrency.
Memory in the Age of AI Agents | 2025 (Dec) | arXiv survey 2512.13564 | https://arxiv.org/abs/2512.13564 | Sec 7.5 Shared Memory in MAS: "naive global sharing also exposed new challenges, including memory clutter, write contention, and the lack of role- or permission-aware access control."
